# RoadModel 评测

通过飞书卡片发起 RoadModel 模型精度与编译精度评测，统一管理材料解析、执行环境、任务状态和飞书报告交付。

用户每次提供**模型交付链接**和**评测数据集链接**。系统解析交付产物、准备评测环境，分别执行两条评测链路，再按约定 PCM 模板生成单次评测报告。模型精度、编译精度和报告生成保持独立 Skill，便于单独调用与组合集成。

## 功能

| 能力 | 说明 |
| --- | --- |
| 飞书工单 | 在现有台架评测 Bot 中提供独立 RoadModel 卡片，接收输入、展示执行状态并返回报告链接。 |
| 交付材料识别 | 从交付记录中的链接及文件内容识别权重、配置、ONNX 和编译包；保留来源与版本绑定，候选有歧义时提示缺项。 |
| 模型精度评测 | 在 LPAI 开发空间执行模型推理、数据读取、GT 适配与指标计算；按已适配的模型和数据契约处理 OCC、视觉分类及轨迹评测项。 |
| 编译精度评测 | 在工作站编排台架执行，对比同版 FP16 ONNX 与板端输出，并独立计算两端相对 GT 的指标。支持已适配的五分网串接。 |
| 开发空间管理 | 首次初始化绑定账号和专属空间；按任务数据准备挂载，通过官方接口查询、启动空间并接续工单。 |
| 结果与报告 | 收集结构化结果和原始来源，按约定模板发布飞书文档，回读核对后回填原卡。 |
| 中断与续跑 | 保存任务状态及检查点，核验留存结果后复用已完成工作；回调去重，报告或通知失败不触发重复推理。 |

## 使用流程

首次部署完成后，在机器人私聊发送 `RoadModel评测`，打开卡片并填写以下两项（[输入示例](../examples/evaluation_submission.json)、[字段结构](../schemas/evaluation_inputs.schema.json)）：

| 必填输入 | 具体内容 | 用途 |
| --- | --- | --- |
| 模型交付链接 | 工程师提交的飞书模型交付记录链接，关联本次权重、配置及同版 ONNX、编译产物。 | 确定评测版本、模型架构与执行所需材料。 |
| 评测数据集链接 | 本次 LPAI 数据集的明确版本链接。 | 两条链路共用，分别解析各评测项的输入、索引与逐帧 GT。 |

账号、GPU 规格、工作站连接和台架配置由部署初始化管理，无需每次填写。模型精度与编译精度共用提交的数据集。各头可读取数据集内不同索引分区；缺少可靠逐帧 GT 的项目标注缺项，不跨版本补齐标签，也不影响其他可评测项。

提交后的处理顺序：

1. **预检材料**：解析两项输入，确认版本、文件角色、数据索引与 GT，冻结本次执行计划。
2. **准备环境**：核对专属 LPAI 空间与数据挂载；空间关闭时请求启动，平台要求确认时等待用户确认后继续。
3. **执行评测**：模型链路在 LPAI 运行；编译链路由工作站通过共享台架队列执行。两条链路独立记录进度和异常。
4. **收集结果**：校验原始结果、实际覆盖范围、指标及来源文件，区分已完成、缺项和失败。
5. **交付报告**：按约定模板生成、发布并回读飞书报告，将链接回填原工单。

任务范围由部署策略和冻结计划确定。小场景验证与全量评测分别记录，不将小场景结果标记为全量完成。台架不可用时，编译链路等待资源，不将离线检查视为真实板端评测。

## 输出

| 输出 | 内容 |
| --- | --- |
| 飞书评测报告 | 单次评测结果，按约定 PCM 参考模板保留对应章节、表头、指标顺序和单位，展示模型精度与编译精度两部分。 |
| 结构化结果 | `pcm.single-eval/v1` JSON，记录执行状态、覆盖范围、指标、产物及来源信息。 |
| 执行凭据 | 任务与材料绑定、文件哈希、检查点、执行日志、收集及发布回读记录。 |

张量一致性与 GT 表现分别呈现，不合成总分。缺少可靠 GT 的项目如实标记，不填零值，不以场景标签代替逐帧标签，也不自动换用其他数据集。

本项目提供单次评测能力。跨版本对比及发版通过判定属于上层业务流程。

## 部署与初始化

### 环境要求

- **本地开发**：Python 3.10 及以上。
- **飞书接入**：已配置的机器人连接、回调处理与报告读写授权。
- **LPAI**：可用账号、CUDA GPU 资源、已登记镜像、数据访问权限及执行端 SSH 配置。当前模型适配器按 GPU 执行，尚未适配 CPU 模式。A100 40GB 共享环境已验证，但 A100 型号、72 核 CPU 和 560 GiB 内存上限都不是通用最低要求；其他 GPU 须先核验镜像、算子兼容性和实际显存占用。
- **编译评测**：可连接工作站和台架，以及原台架评测工具包与对应运行环境。

### 安装源码

```bash
git clone https://github.com/Inner-vic/roadmodel-evaluation.git
cd roadmodel-evaluation
python -m pip install -e .
```

按需安装 GT 与视觉适配依赖：

```bash
python -m pip install -e ".[gt,vision]"
```

以上安装提供本项目代码及所声明的可选依赖。模型运行镜像、供应方模型源码、台架原生工具和飞书、LPAI 客户端需要按部署环境另行配置。

### 绑定运行环境

首次部署先运行配置引导：

```bash
python -m pcm_eval configure-environment --output initialization-request.json
```

引导会询问参考 GPU 开发空间的名称、namespace 和集群，通过官方只读接口提取资源规格、队列、镜像和 SSH 入口，再询问本人的 LPAI 账号与已有 SSH 凭据引用。飞书身份由当前授权核验。确认摘要后只生成配置，不创建空间、不启动评测，也不复制参考空间的账号、UID、固定节点或数据挂载。

可以选择其他集群、队列和 GPU 规格的参考空间，也可用 `--template-file <环境模板JSON>` 加载审核过的模板。参考空间可以用于了解规格，但不代表当前账号有镜像、队列或数据权限；初始化仍会校验实际归属、配置与数据挂载，小场景运行才验证模型兼容性。没有合适参考空间时，应先在 LPAI 选择可访问的资源模板，不能凭空填写资源套餐 ID。部署者也可参照[初始化请求示例](../examples/installation_request.example.json) 手工配置。

生成配置后执行初始化：

```bash
python -m pcm_eval initialize-environment \
  --request initialization-request.json \
  --state-dir .runtime/installation \
  --output evidence/initialization
```

上面的命令先核验并保存初始化进度。需要通过官方 SDK 创建时，在配置引导中通过 `--dataset-ref` 指定初始 OCC 数据版本，并在初始化命令中追加 `--create-provider official_sdk --sdk-python <已配置官方LPAI_SDK的Python路径>`。资产文件 SDK 和官方 LPAI SDK 可能位于不同解释器，不能混用。没有可用 SDK 时，可由 Codex 根据保存的初始化计划通过 Computer Use 协助完成。

账号达到平台空间名额上限时返回 `BLOCKED_CAPACITY`，保留原空间名称与创建意图，不自动删除旧空间。释放名额后重新执行同一条初始化命令；SDK 在确认此前没有发出创建 POST 的情况下重新核验并继续，已有或未知的创建请求只回读对账。停止空间不会释放空间数量名额。

初始化将安装实例、账号和专属空间 UID 绑定。创建空间使用官方 SDK 认证的 Notebook API；遇到需要页面操作的情况，由 Codex Computer Use 协助。日常启停通过官方 `lpai-agent` 接口处理，平台确认步骤仍需用户操作。

`BOUND` 表示空间绑定已核验，随后还需将绑定同步到机器人运行环境。复用部署包中审核过的桌面 Agent 与服务端基础配置，在同一初始化命令追加 `--base-agent-config agent.base.json --agent-config-output generated/agent.json --local-state .runtime/evaluation-agent` 和 `--base-server-config evaluation.base.json --server-config-output generated/evaluation.json`，导出本次账号及空间的配置。基础配置由现有部署提供，包含工作站连接、原台架工具和报告发布适配；不能直接把示例空间信息当作可运行的部署配置。安装导出配置前确认没有正在执行的 RoadModel 工单，保留原配置备份，并核对两端的 Agent ID、空间 UID 和 SSH 端口一致；不要中断共享台架的其他任务。

根据任务输入核对并准备数据挂载，模型评测数据在 LPAI 内读取。对于当前集群无法挂载的数据，可在明确授权的小场景范围内，通过官方资产接口仅准备必要图片与逐帧 GT，并保存独立的资产文件校验收据。此适配最多准备两帧，不代表整份数据已挂载，也不自动扩展为全量；使用前需配置具有官方资产 SDK 的独立解释器。编译链路按冻结帧清单准备工作站所需文件并复用缓存。评测结束后保留空间供连续任务使用，沿用配置的四小时自动关闭策略。

初始化参数见 `python -m pcm_eval initialize-environment --help`。`configs/` 中的既有路径和资源标识为参考绑定，新环境部署前必须核对，不能直接作为通用默认值使用。

## 开发

查看命令行接口：

```bash
python -m pcm_eval --help
```

运行不依赖真实材料的调度单元测试：

```bash
python -m unittest tests.test_batch_schedule -v
```

部分集成测试依赖未入库的模型、台架工具包及原始评测证据，需要在对应环境执行。单元测试和离线检查不能替代真实双链路验收。

| 路径 | 职责 |
| --- | --- |
| `pcm_eval/` | 输入解析、任务编排、执行适配、结果收集和报告生成。 |
| `skills/` | 模型精度、编译精度、报告交付和开发空间准备的 Skill 定义。 |
| `tools/` | 执行器、后台 Agent、部署与检查工具。 |
| `schemas/` | 请求、结果与交付数据结构。 |
| `examples/`、`configs/` | 输入示例和运行配置参考。 |
| `tests/` | 单元测试、协议验证及集成测试。 |
| `docs/` | 报告模板与填报规则。 |

## 支持范围与限制

- 历史验收已验证配置引导、新建专属空间初始化及 v3.2.2 的三输入流程（当时为弥补视觉 GT 缺项另给视觉数据；当前入口已恢复单数据集）：真实卡片提交后自动核验材料、执行模型精度与台架编译精度、发布飞书报告并回填原卡，执行期间无需后台手动补救。模型 OCC 使用 `26-10-20-1`，视觉分类使用 `26-08-14-0`，各 1 场景、2 帧；编译精度使用 OCC 数据中的同两帧。5 张报告表格的指标通过发布后回读核验，见[小场景报告示例](https://li.feishu.cn/docx/DEMO00000000000000000000001)（需具备飞书访问权限）。
- 上述验收覆盖已适配版本的小场景，不代表全量评测已完成，也不代表任意模型架构和任意数据格式都可直接执行。开发空间启动仍遵守平台确认要求，台架执行仍依赖可用的物理连接和共享队列。
- 材料识别不依赖单一固定字段名，但仍须通过版本、内容与执行契约校验。有多个无法消歧的候选时阻止对应链路，提示补齐信息。
- 各项评测独立检查同一输入数据集内的逐帧 GT，报告分别注明实际范围和不可计算原因。缺 GT 项保持缺项，不自动换用历史视觉数据。
- 编译链路采用逐帧台架执行、2 路 ONNX 参考预取与 4 路 GT 计算。多帧研究代码保留为未启用候选。
- 仓库不包含模型、数据集、第三方台架工具包、凭据、登录态和运行数据库；克隆源码后需完成授权、材料准备与环境初始化。
